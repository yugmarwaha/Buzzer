# frontend

## Purpose
Three independent React + Vite + Tailwind apps that talk to the one backend: **host** (big-screen game controller), **player** (mobile answering client), **admin** (management console). Each has its own `package.json`, Vite/Tailwind/TypeScript config, and `src/`; there is no shared npm package (and no `package.json` or `node_modules` in `frontend/`), but these files here are shared by all three apps: `theme.css` (the color tokens for dark and light, source of truth, plus shadow/alpha/motion tokens, the page backdrop, `.glass*`, keyframes, `.stagger`, `.lift`, `.skeleton`, global focus-ring, `color-scheme`, reduced-motion and reduced-transparency rules), `tailwind.preset.ts` (a plain object with no imports that maps the tokens to Tailwind class names, plus fonts, type scale, radius, shadows and `animate-*` names), and `scripts/` (the theme checks, see `scripts/CLAUDE.md`). Each app imports `../../theme.css` in `src/main.tsx` and lists the preset in its `tailwind.config.ts`.

## Contents
- `host/` — course-first: pick a course, then its quizzes, rooms, roster, and sessions; runs the live game. Context: `host/src/CLAUDE.md`.
- `player/` — joins by room code, identifies (guest, NetID OAuth2, or local login), and answers questions; signed-in players also get Past Quizzes. Context: `player/src/CLAUDE.md`.
- `scripts/` — `check-theme.mjs` and `check-raw-colors.mjs`; run from the repo root. Context: `scripts/CLAUDE.md`.
- `admin/` — admin-first REST console: users, courses, course access, guests; links to the Host app for quiz/roster/session work. Context: `admin/src/CLAUDE.md`.

## How it fits in
All three call the backend under a hardcoded `/api` base path via their own `lib/api.ts`, and read the JWT from `localStorage` key `token`. Only host and player use socket.io. Both open the connection from `pages/game/GameLayout.tsx` and share the same event vocabulary: the host emits `join_room` (role HOST), `host_advance`, and `host_lock_question`; the player emits `join_room` (role PLAYER) and `submit_answer`. Admin uses REST only (`/admin/*`); the Host app's REST calls are mostly `/host/*`.

Every app has the same layout: `pages/` → `components/ui` + `lib/`, with `lib/` at the bottom. Each also has its own `components/ui/{button,card,input,badge,progress,spinner}.tsx` plus `motion.ts` (`staggerStyle`), and `lib/utils.ts` (`cn`, a tailwind-merge that knows the preset's custom class names); host and player each also have `TimerBar` and a `types/game.ts`; host adds `types/host.ts` (`/host/*` REST shapes) and `components/charts/` (inline-SVG charts for results and game over), and player adds `types/past.ts` (Past Quizzes shapes).

| | host | player | admin |
|---|---|---|---|
| Sign-in | NetID OAuth2, or username/password | guest, NetID OAuth2, or local login | username/password |
| Route guard in `App.tsx` | token-exists on `/courses/*`, `/quizzes/*`, `/game/:code` (`/home` → `/courses`) | none | unexpired ADMIN token (`RequireAdmin`; expiry or a 401 returns to `/login`) |
| Socket.IO | yes (drives the game) | yes (answers) | no |
| `lib/api` verbs | get/post/put/patch/delete, `postForm`, `download` (`ApiError` with status) | get/post (`ApiError`) | get/post/put/patch/delete, `postForm`, `download` |

## Gotchas
- **Duplicated code is deliberate but easy to desync.** A fix to `TimerBar`, `api.ts`, `cn`, or `components/ui/ThemeToggle.tsx` (an identical copy in each app; `npm run check:theme` fails if they drift) in one app does not reach the others, and the differences are real (the theme files above are the one exception: they are shared, not copied). Real differences exist for example player's `utils.ts` also has `isTokenExpired`, and admin's `api.ts` has upload/download helpers).
- **Server-side authorization is the real gate** in all three apps; client guards check a token (the Host and Admin also check expiry and role) and no app refreshes tokens.
- **Socket payload types are defined separately in each app** (`host/src/types/game.ts` and `player/src/types/game.ts` are not identical) and must stay in step with `backend/app/websocket/`.
- **Adding a question type touches host and player:** the host app's question editor (`host/src/pages/QuestionEditorPage.tsx`, moved from admin in T4) builds `config`/`answer_data`, host renders results/game over, and player renders and answers the question (plus the shared recap in `player/src/components/QuestionRecap.tsx`). See `backend/app/CLAUDE.md`.
- **Run the apps with `npm run dev` / `npm run build`, not bare `npx vite`.** The scripts and `postcss.config.js` name `vite.config.ts` and `tailwind.config.ts` explicitly, so stale generated `tailwind.config.js` / `vite.config.js` files (from older builds) are ignored. `tsconfig.node.json` sets `rootDir`/`outDir` so `tsc -b` emits into `node_modules/.tmp` and nothing is generated beside the sources. Each `vite.config.ts` sets `server.fs.allow` so Vite can serve `theme.css` from outside the app root.
- **Theme switching:** each `index.html` has the same inline script (storage key `buzzer-theme`; sets `data-theme` before React; follows the OS until a choice is saved; syncs across tabs through the `storage` event (clearing the stored value in another tab returns this tab to following the OS); sets `color-scheme` and the `<html>` background inline so the first paint matches; exposes `window.buzzerTheme.set(theme)`; updates `<meta name="theme-color">`). `components/ui/ThemeToggle.tsx` calls it and watches `data-theme`. Placement: Admin sidebar footer plus fixed top-right on the login page; Host top-right, except top-left on `/game/*`; Player fixed top-right with a reserved top strip and a banner offset variable. `npm run check:theme` verifies the three script copies, runs each copy in a fake browser to check the OS-preference default and that a saved choice persists across reloads, the `theme-color` hex values, and that the host and player `PinGrid.tsx` copies match apart from the header comment. The `buzzer-theme` key is per origin, so host, player and admin on separate ports do not share it.
- **Colors come from tokens**, not Tailwind palette classes or hex: `bg-page`/`bg-surface`/`bg-raised`, `text-primary`/`text-secondary`/`text-muted`, `border-line`, `bg-accent` and the other names in `theme.css`; elevation is `shadow-soft`/`raised`/`float`/`overlay` (plus `glow`, `button`; legacy `shadow-card` is `none` in dark). Rules: never `text-accent` (use `text-accent-text`), no text opacity modifiers, translucent fills only as `bg-page/NN` or `bg-surface/NN`, no `bg-line`, no class names built from fragments (`bg-${x}`, reported by the scanner), no named colors (`color: 'white'`, `fill="red"`), and `theme-exempt` (one finding per marker) is allowed only for the QR white wrapper and the `theme-color` hex values. Conventions: controls `rounded-lg` (12px), cards `rounded-xl` (16px), glass and question cards `rounded-2xl`, badges `rounded-pill`, the focus-visible ring recipe, lucide icons instead of decorative emoji, disabled buttons as a muted label on a raised background (not opacity). Run `npm run check:theme` (contrast, token parity) and `npm run check:colors` (raw colors; add `-- --strict` to fail) from the repo root. Plan and implementation log: `docs/plans/ui-themes.md`.
- **Build config at each app root** is not covered by a context doc. Per `vite.config.ts`, production builds use base paths `/host/`, `/player/`, `/admin/`, dev uses `/` with `/api` proxied to `localhost:8000`.
- **The repo-root `package.json` (outside `frontend/`) orchestrates all three apps** via `--prefix` scripts: `npm run dev` runs host+player+admin concurrently (`dev:host`/`dev:player`/`dev:admin` run one at a time), `build` and `install:all` run all three in sequence. It's separate from each app's own `package.json`.
- **Visual refresh foundation (docs/plans/ui-themes.md section 12).** Type: `text-display`/`title`/`stage`/`heading`/`subheading`/`body-lg`/`body`/`caption`/`label`/`stat`/`timer`/`code` (size, line height, tracking, weight together); always `tabular-nums` on scores and timers. Glass: `.glass`, `.glass-strong`, `.glass-subtle` (or `<Card variant="glass">`) with a radius and padding; never add `bg-*`/`shadow-*` on a glass element, and never cover the screen with an opaque `bg-page` wrapper (it hides the `body::before` backdrop). Text tokens on glass are contrast-checked by `check-theme`. Empty chart bars and progress tracks use `bg-track`. Motion: `animate-fade-in`/`slide-up`/`slide-down`/`scale-in`/`pop` (entrances, staggered by `.stagger` or `staggerStyle(i)`), `animate-pulse-soft`, `animate-shimmer`/`.skeleton`, `animate-tick` (with `key={value}`), `animate-shake`; `.lift` for clickable cards; looping animation only for the low-timer pulse, loading shimmer/spinners, and waiting indicators (live dot, lobby waiting dots); `duration-fast`/`base`/`slow`, `ease-smooth`/`swap`/`spring`. Reduced motion turns all of it off (spinners still turn); reduced transparency makes glass solid. A new preset class name that tailwind-merge does not know must be added to the `extendTailwindMerge` list in all three `lib/utils.ts`, or `cn` may drop a class.
