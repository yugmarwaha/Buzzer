# scripts

## Purpose
Zero-dependency Node 20 checks that enforce the T9 theme contract (docs/plans/ui-themes.md, sections 3.1-3.6). Run manually before every merge request and before submission; they are not in CI.

## Contents
- check-theme.mjs — parses the RGB-channel tokens in `../theme.css` per theme block (`:root, :root[data-theme="dark"]` and `:root[data-theme="light"]`; every block present is checked), prints every WCAG 2.1 contrast pair from spec 3.3 with its ratio and PASS/FAIL, checks that `../tailwind.preset.ts` names match `theme.css` and sit under the Tailwind key from the 3.1 table, and that the inline theme scripts in `*/index.html` are identical and their `theme-color` hex equals `page` per theme. Non-color tokens are recognized by prefix: themed `--shadow-*`/`--alpha-*` must exist in both theme blocks; static `--dur-*`/`--ease-*`/`--blur-*`/`--stagger-*` sit in one plain `:root` block. Name parity reads only the color keys of the 3.1 table and fails if any other preset key maps a color variable. A glass section checks every text token on the bare backdrop and on `glass-subtle`/`glass`/`glass-strong` against the worst of 20 backdrop colors (page and page-2, each blob at its peak, each blob pair), using the `--alpha-*` values; pairs also cover `accent-text` on `accent-hint` and status fills on `track`. Exits 1 on any failure. It also fails if the three `src/components/ui/ThemeToggle.tsx` copies are not byte-identical, or if the host and player `PinGrid.tsx` copies differ anywhere except the header comment line that names the other app. The composite section checks `primary`, `secondary`, `muted`, `accent-text` and `danger` on `surface/60` over `page`. Unused tokens (`info*`, `medal-*`, `timer-3`, `success-fg`) were removed from `theme.css`, the preset and these lists; re-add them in all three places together.
- check-raw-colors.mjs — scans `{host,player,admin}/{src,public}/**/*.{js,jsx,ts,tsx,css,svg,html}` and `*/index.html` for raw palette utilities (`bg-slate-800`, `text-white`, ...), hex/`rgb()`/`hsl()` literals (`rgb(${channels})` built from tokens is allowed), named colors in `color:`/`background:`/`fill=`/`stroke=` literals, class names built from fragments (`bg-${x}`, `"bg-" + x`), `fillStyle`/`strokeStyle` strings, `text-accent` as text, `text-*/NN`, and `bg-*/NN` other than `bg-page`/`bg-surface`/`bg-black`. Prints counts per file, category and app. `--verbose` lists every hit with its line.
- raw-colors-allow.txt — repo-relative paths exempt from `--strict`, one per line, `#` comments. Intended to be empty: the T7/T8 screens it once listed were converted to tokens early (docs/plans/ui-themes.md section 11), so it should hold only its comment header. Must stay empty through submission.

## How it fits in
Run from the repo root: `npm run check:theme` and `npm run check:colors` (root `package.json`; `frontend/` has no `package.json`). `check:colors` is report mode (always exit 0); `npm run check:colors -- --strict` (or `node frontend/scripts/check-raw-colors.mjs --strict`) fails on anything outside the allowlist and is the merge gate. Add `--verbose` to list each hit.

## Gotchas
- check-theme reads the preset with a regex, never by executing TypeScript; keep the preset a flat object of `'name': 'rgb(var(--name) / <alpha-value>)'` entries or the parser will miss names.
- The light block must define every token the dark block has, or check-theme fails.
- check-raw-colors skips comments, `transparent`/`current`, `theme.css`, and one finding per `theme-exempt` marker on a line (the first one; a second raw color on the same line is still reported). Only the QR wrapper and the `theme-color` hex values may use it.
- Fragment class names are now reported by the `fragment-class` rule; the spec forbids them.
- `bg-black/NN` is exempt from the opacity rule but still counts as a raw palette utility (scrims become `bg-page/80`). A `#abc`-like string (e.g. a URL fragment) is reported as hex; mark it `theme-exempt` if legitimate.
